# ADR: Preserve SET EXACT as VM state for character equality

Status: Accepted, 9 October 2026

dBASE III PLUS defaults to SET EXACT OFF for character comparisons. That
compares the entire right-hand operand against the beginning of the left-hand
operand; `"JACOBSON" = "JACOBS"` is true, but reversing the operands is false.
SET EXACT ON uses full value comparison with trailing spaces ignored.

The VM owns one runtime-global setting, not a per-work-area flag. Both the
main VM instruction interpreter and separately evaluated filter bytecode
share the same comparison helper, ensuring filters respond to changes in
SET EXACT without recompiling their expressions. The `==` operator emits a
separate strict comparison opcode, preserving the existing source subset.

This does **not** resolve historic differences across Clipper, FoxPro, Visual
FoxPro and modern dBASE in trailing-blank treatment of `==`, collations or
string-order operators. These are compatibility-profile test obligations.

Reference: dBASE Language Handbook, SET EXACT:
